# 状态、交接与版本约定

## 唯一进度入口

每课维护 `course-state.md`，记录课程 ID、采用的工作流版本、课程成果版本、当前阶段、状态、定位卡、已启用交付物、下一监督点、当前轮范围、待办、阻塞和相关文件位置。它是进度与决策入口，技术内容仍以教学底稿为准。

阶段状态使用未开始、进行中、待评审、需修改、通过、暂缓。中断或交接前更新；恢复时核对入口、实际文件、最近决策和待评审版本。状态与文件冲突时先核实并纠正，不重复创建课程。工具失败保存已完成工作，注明缺失产物及替代方案，不擅自降低交付标准。

## 启动确认与产物意向

正式启动课件开发时，`course-state.md` 必须记录主题理解卡的版本与用户确认状态，以及交付物清单。主题名称、用户提供的参考网页或一句宽泛需求都不能代替主题理解确认。

交付物逐项使用以下状态：

- **制作**：已明确纳入。
- **不制作**：用户明确排除。
- **待定**：尚未决定，框架评审时处理；不得开始制作，也不得在交付说明中宣称包含。

启动时记录课程负责人期望的产物，框架评审时锁定最终范围。后续新增、删除或推迟已锁定产物时，说明受影响的教学目标、时间预算、制作成本与已通过评审，并按影响重新评审相关内容。

## 阶段交接最低要求

| 阶段 | 输入 | 必须形成的产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 选题 | 需求、系列地图、受众基础 | 主题理解卡及确认、交付物意向清单、定位卡、能力目标、边界、时间口径 | 用户认可主题与定位版本；交付物状态已记录 |
| 框架 | 已通过定位 | 候选路径比较、章节依赖、案例主线、目标与理解证据、附件选择 | 用户认可对应版本 |
| 调研 | 已通过框架 | 论断来源表、教学案例、冲突及未决项 | 核心论断有依据；影响目标或框架的冲突先交用户决定 |
| 样章 | 调研结论、核心难点 | 页面、图解、讲稿、理解问题、风格样页、用时估算 | 用户认可对应版本 |
| 开发 | 已通过样章 | 完整底稿、课件、讲稿、已选附件及对应表 | 可实际检查，明确尚未完成项 |
| 走查与试讲 | 可审视课程版本 | 阅读和试讲记录、问题清单、证据等级 | 用户评审并确定修订范围 |
| 修订验收 | 已确认问题清单 | 修订版、问题复核、载体联动验收记录 | 必修项关闭，已选附件通过，用户认可版本或明确接受限制 |
| 复盘 | 验收及使用反馈 | 课程改进待办、流程改进提案、试跑记录 | 记录结论；不自动启动下一轮 |

调研及开发内部完成检查可由主 Agent 执行，不额外增加逐项审批。选题、框架、样章、试讲修订与最终验收是主要人工监督点；已有明确授权不重复询问。

## 审批与影响传播

审批记录包含评审 ID、成果路径及版本或提交号、日期、评审人、决定、条件与未决项。聊天批准应转录到记录，并指向当时实际版本。未答复不算通过。

修改能力目标、课程边界、概念机制、章节依赖或时间口径时，列出影响单元与载体，把相关审批标为需重新评审；无影响的审批保留。错别字、已授权排版修正不使整课审批失效，但仍记录变更。旧版本保留可追溯记录。

## 指令冲突处理

用户要求：如果其指令不符合闭环工作流规范，Agent 必须主动提醒。此规则适用于后续课程开发，不仅限于当前课程。

- 在执行有关动作前，对照当前阶段、已批准成果及适用约束，判断是否存在实际冲突，例如框架未通过就要求正式制作全课、跳过样章或试讲、将可选附件默认加入，或变更范围但不处理受影响审批。
- 提醒应简短具体：说明哪条规则来自哪个文件、当前缺少什么、直接执行有什么影响，并提出最小可行的调整。避免笼统地说“不符合流程”。
- 用户尚未明确批准例外时，不执行依赖该例外的动作；可以继续不受影响的讨论、草案整理及已授权工作。请求讨论后续内容或制作供评审草案，本身不等于要求通过审批或正式跨阶段开发。
- 用户明确要求本课例外或修改流程时，以其指令为准；先说明相关影响，已有明确决定时不重复索要确认。普通制作请求不能自动当作知情豁免，未回复也不算同意。
- 将冲突、提醒、用户决定、适用范围和受影响成果记录到课程状态或决策记录。本课例外不自动改为长期规则；长期变更更新 Skill 及版本。不得把获准的流程例外记作原评审已通过。

提醒示例：“按 workflow.md 的样章要求，框架通过后需先评审核心难点样章。目前样章尚未通过，直接制作全课可能放大解释和风格问题；建议先完成该样章，再展开全课。”

## 系列地图与教学底稿

系列维护 `series-map.md`：课程 ID、顺序、状态、提供的能力、依赖能力及对应课程、术语、案例、范围和有意复习点。新课选题和框架变更时检查遗漏前置、意外重复及循环依赖；首课和未定后课明确注明，不编造既有课程。

教学单元使用稳定 ID，例如 `U01`，图示 `F01`、案例 `C01`、论断 `CL01`，删除后不复用。底稿记录解释、例子、边界和来源。载体对应表列出这些 ID 在 PPT 页、讲稿段落、教材章节、视频分镜或时间段、Demo 文件中的位置及版本。不要求所有载体自动生成，但不能用未更新底稿直接覆盖人工修改。

## 迭代和收尾

问题分为必须修复、建议优化、后续增强。事实错误、核心目标缺失、关键不可读或已选产物不可用属于必须修复。每轮明确范围及用户给定的时间/成本限制；新想法进入待办，改变范围时说明影响。

必须修复项关闭、当前轮承诺完成、用户通过验收后结束本轮。反复无改进、依赖不可用或超出约定预算时提交具体原因、已尝试方案和取舍，由用户决定，不无限循环或自行宣布完成。

## 工作流版本迁移

新课记录采用的版本，进行中的课程默认保持原版本。升级提供规则差异、影响阶段和迁移成本，由用户决定是否及如何迁移。临时指令优先于默认规则；单课偏好不自动进入全局 Skill。

一个主 Agent 对状态、最终整合及验收负责。使用获准的辅助 Agent 时给出有限任务、输入版本、预期输出和权限；返回结果需由主 Agent 核实后整合，不能直接视为验收通过。
