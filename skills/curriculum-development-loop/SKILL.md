# Curriculum Development Loop

先判断用户希望讨论流程、开发新课，还是修订已有课程。讨论模式只形成方案，不擅自开始制作课程。继续长任务前从课程的 `course-state.md` 读取进度，核对实际文件及评审版本，不能只依赖对话记忆。

## 核心约束

- 默认学员具有 1～3 年软件研发或算法开发经验；如用户另有指定，以指定为准。
- 每课课件阅读目标为 30～40 分钟；定位时确认纯阅读或完整核心学习口径。未确认时按纯阅读估算，思考、视频、Demo 操作及等待另记，不静默扩大预算。
- 与用户共同确定选题及框架；框架通过后开展系统调研，再进入正式内容开发。
- 技术解释涵盖机制、示例、取舍及失效边界，类比需要交代局限。
- 网页、PDF、概念视频和 Demo 是独立可选项。制作前确认教学用途与范围。

## 执行路径

按 [工作流参考](references/workflow.md) 完成当前阶段，不跨过待用户评审的关键节点。每次评审提交具体可审视成果、建议及待决定问题，避免逐个小步骤反复确认。

1. 共同选题：形成定位、能力目标、范围和前后课关系。
2. 框架评审：比较不同教学路径，明确案例主线、认知转折和理解证据。
3. 系统调研：按框架问题收集高价值资料，记录来源、版本、论断与用途；发现重大冲突返回框架评审。
4. 教学样章：先制作核心难点，验证技术深度、解释、话术、视觉与时间密度。
5. 完整开发：按通过的样章展开内容，并制作已选交付物。
6. 阅读走查及试讲：检查难度、术语、节奏、吸引力和理解效果。
7. 修订验收：追踪问题关闭与载体联动，必要时重新试讲相关部分。
8. 复盘：区分本课修改和长期流程建议，长期规则经用户确认后纳入。

## 制作与持续维护

新建课程或恢复长任务时读取 [状态与交接约定](references/operations.md)，使用 [项目记录模板](assets/course-records.md) 建立所需记录。系列衔接、内容单元、引用和载体对应关系都应可追踪。模板按需实例化，不为未启用附件创建空目录。

评审、试讲、交付验收时读取 [质量与试跑规范](references/quality.md)。审批绑定具体成果版本；实质改动使受影响审批重新待评审。没有真实目标学员反馈时，不宣称教学效果已验证。

默认一个主 Agent 维护统一状态，按需调用制作能力；仅在确有独立核验或并行制作收益、且获得授权时使用其他 Agent，并约定输入、输出、责任人与整合检查。

手绘暖色风、技术架构蓝图风等视觉风格可以调整；风格变化保持技术语义、术语和符号含义一致。优先使用可编辑文字与技术关系图。

按已启用交付物调用可用的制作能力。先确认工具实际可用；脚本、分镜、网页动画或截图均不得冒充视频成片、可运行 Demo 或已完成的 PPT。

维护任务书、来源、决策、评审问题及版本记录。更改定义时追踪 PPT、讲稿以及已启用教材、视频与 Demo 的相关内容。不要将课程开发授权视为自动发布、上传、发消息或启用定时同步的授权。

外部方法来源及其适用限制见 [参考说明](references/provenance.md)。
