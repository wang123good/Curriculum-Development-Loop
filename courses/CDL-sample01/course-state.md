- 主题理解卡：待确认；当前技术理解为“有副作用工具的执行结果不确定时，Agent 如何依据证据与工具能力决定查询、重试、等待或升级”，尚未获得用户正式确认。
- 学员：1～3 年研发或算法工程师；建议具备 HTTP 调用、超时和基础异常处理经验，实际基础待确认。
- 培训类型建议：工程能力提升；适合开发工具调用或有副作用自动化流程的工程师，其他人员选学。
- 问题假设：将调用超时误判为未执行，对有副作用工具重试可能导致重复业务操作；需求尚无真实部门案例验证。
- 教学案例 C01：创建工单已成功但响应未被收到，再次调用产生重复工单。构造案例，不冒充真实项目。
- 核心问题：结果未知时，如何决定是否重试并控制重复副作用？
- 能力目标：识别明确失败与结果未知；结合操作性质和工具能力选择重试、查状态或人工确认；解释业务操作标识与服务端幂等处理的职责。
- 达标任务建议：给定调用记录与工具契约，判断处理方式，说明理由、验证步骤及方案限制。
- 必讲建议：超时语义、重试责任边界、业务操作标识与幂等处理、状态确认及停止升级条件。
- 排除建议：完整分布式事务、消息队列可靠投递体系、通用 Agent 框架源码、生产级平台搭建；不承诺实现全局 exactly-once。
- 简单基线：普通 HTTP 客户端重试；比较 Agent 重新决策或重新生成调用带来的额外责任问题。此处为设计假设，待调研核实。
